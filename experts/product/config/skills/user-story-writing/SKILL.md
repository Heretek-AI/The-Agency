# User story writing

## When to use

Use when intent needs turning into buildable work. Do not write stories
for work already sliced by the Director.

## Procedure

1. Name the user, the need, and the reason it matters to them.
2. Split until each story fits one expert and one sitting; push the rest
   to the backlog explicitly.
3. Attach acceptance criteria (see acceptance-criteria) before calling a
   story ready.

## Good result

Each story is buildable, testable, and small; the backlog shows what was
deferred and why.
