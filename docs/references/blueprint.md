Here is the architectural blueprint for how we take OpenCode V2 to its ceiling—turning it into a synchronized, multi-tier engineering organization that ships production software and high-craft UIs while staying 100% upstream-compliant with OpenCode Go ($10 / 10B tokens) and requiring zero core fork maintenance.1. Why Coding Harnesses Produce "Hot Garbage" & "AI Slop" UIsCurrent harnesses fail on complex products because of two structural flaws in how they run models:The "Single-Brain Self-Grading" Trap (Why Code Turns into Hot Garbage): In stock OpenCode, a single Build agent tries to hold product requirements, system architecture, database schemas, backend logic, frontend components, and test verification inside one drifting context window. Worse, the same agent that takes a lazy shortcut also grades its own work. When an import fails or a test breaks, a single agent will often delete the assertion, widen a type to any, or mock out the broken function just to finish the turn.Blind JSX Authoring (Why UIs Look Like Generic AI Slop): Coding agents write CSS and JSX completely blind. Without an explicit design-token system, models regress to the statistical average of training data (neon purple-to-blue gradients, arbitrary p-3 next to p-5, unaligned cards). Without a live DOM geometry loop, a text model cannot tell that line-height: 1 clips descenders (g, y, p), that two flex items collide at 768px, or that muted text on a secondary surface fails WCAG contrast (< 4.5:1).2. Exploiting Five Hidden V2 Primitives to Build an Engineering CompanyBy inspecting packages/core, we found that OpenCode V2 (v2.0.26) already contains the exact primitives needed to run a hierarchical software company inside a single local plugin (~/.config/opencode/plugins/swarmos-plugin.ts), without modifying a single line of opencode.provider.opencode or model-request.ts:Unlocking 4-Tier Organizational Depth (experimental.subagent_depth: 4):
In packages/core/src/tool/plugin/subagent.ts:132, V2 defaults subagent_depth to 1 (which blocks a Manager subagent from spawning Engineer or QA subagents). Setting "experimental": { "subagent_depth": 4 } in opencode.json unlocks a 4-tier hierarchy:Tier 0 (primary): director (VP of Product & Engineering)Tier 1 (subagent): architect (Principal Architect), manager (Engineering Manager), release-ops (Release Engineer)Tier 2 (subagent): staff-backend (Systems Engineer), staff-ui (Design Engineer), qa-adversary (Red-Team QA Lead)Tier 3 (subagent): explore (Codebase Reconnaissance)
Because every child session is spawned via Session.create({ parentID: context.sessionID }) (subagent.ts:194), every request in the entire hierarchy carries valid x-opencode-session-id and x-opencode-parent-session-id headers to OpenCode Go.Enforcing Separation of Powers via agent.permissions (tool.ts:242 & subagent.ts:251):
OpenCode V2 filters both the tool snapshot (Tool.snapshot(permissions)) and the Available subagents: list (SubagentTool hook) per agent based on agent.permissions. In swarmos-plugin.ts, we use this to enforce organizational law in code:director and manager are denied edit: Leadership agents cannot write hasty hotfixes themselves; they must delegate through locked contracts and engineering tasks.Reporting lines are hardware-locked: director can only spawn architect, manager, explore, and release-ops. manager can only spawn staff-backend, staff-ui, qa-adversary, and explore.qa-adversary is denied edit on src/** and allowed edit only on **/*.test.*, **/*.spec.*, and e2e/**: The QA agent cannot "fix" a bug by weakening production code—it can only write adversarial tests, run browser/CLI checks, and issue a PASS or REJECT receipt.Replacing the "Telephone Game" with a Shared Organizational Blackboard (tools.org.*):
When subagents communicate only via prose summaries, exact TypeScript interfaces and CSS token names get lost. swarmos-plugin.ts registers a tools.org namespace in Code Mode (execute) backed by .opencode/org/board.json:tools.org.init_project: Locks the Product Charter and chosen UI Aesthetic Archetype.tools.org.lock_contract: Records the exact file paths and invariants of the schemas/types created by architect.tools.org.create_task: Assigns explicit ownedPaths and optional Git worktrees to staff-backend and staff-ui so parallel engineers never collide on FileMutation.withLock.tools.org.submit_qa_receipt: Records cryptographic PASS / REJECT verdicts from qa-adversary.Best-of-N Worktree Tournaments Powered by 10B Muse 1.3 Tokens:
Because 10B tokens/month makes test-time compute practically free, manager can provision two isolated Git worktrees via tools.opencode.worktree_create, spawn two parallel staff-backend or staff-ui subagents (background: true) to solve a hard problem independently, and have qa-adversary test both worktrees—merging whichever implementation passes with zero compiler or geometry defects.The Deterministic Visual & DOM Geometry Engine (tools.ui.get_audit_script + @opencode/plugin-browser):
Instead of letting staff-ui guess whether a page looks good from raw code, swarmos-plugin.ts pairs an Anti-Slop Aesthetic Contract with a mathematical DOM inspection script (DOM_GEOMETRY_AUDIT_SCRIPT) executed inside OpenCode's attached browser (tools.browser.evaluate) alongside tools.browser.screenshot.3. How the Visual & DOM Geometry Engine Fixes UI Generation (Part 6.3 & 6.4 in Canvas)When staff-ui or qa-adversary runs tools.ui.get_audit_script inside tools.browser.evaluate, the injected inspector walks every visible DOM node in the live Chromium tab and mathematically flags six classes of visual defects that LLMs normally miss:Horizontal Page & Container Overflow (page-horizontal-overflow / element-overflow-x): Detects any element where scrollWidth > clientWidth + 2 without intentional scroll behavior.Sibling Bounding-Box Collisions (sibling-collision): Computes getBoundingClientRect() intersections across sibling elements to catch overlapping buttons, badges, or text labels.Row Baseline & Alignment Jitter (row-baseline-jitter): Flags sibling cards or controls in a horizontal row whose top coordinates drift by 0.5px–3.5px (a classic sign of mismatched padding/line-height).WCAG Luminance Contrast Failures (low-contrast): Traverses up the DOM tree to resolve the effective opaque background color, calculates relative luminance against computed color, and flags body text < 4.5:1 or large text < 3.0:1.Descender Clipping (descender-clip-risk): Flags text elements where lineHeight / fontSize < 1.15 is combined with overflow: hidden.Sub-Minimum Touch/Click Targets (tiny-interactive-target): Flags interactive <button>, <a>, or <input> elements smaller than 24x24px.How to Launch It TonightCopy swarmos-plugin.ts from Section 6.4 of the Canvas document into ~/.config/opencode/plugins/swarmos-plugin.ts (alongside muse-harness.ts from Section 5.1).In ~/.config/opencode/opencode.json, add "~/.config/opencode/plugins/swarmos-plugin.ts" to "plugins" and set "experimental": { "subagent_depth": 4 }.In any project, run /ship <your product or feature specification> (or press Tab / agent selector to choose Director). The Director will interview you if anything is ambiguous, initialize .opencode/org/board.json, dispatch the Architect to lock contracts, and hand off to the Engineering Manager to run Staff Backend, Staff UI, and QA Adversary in synchronized loops until the product ships.
